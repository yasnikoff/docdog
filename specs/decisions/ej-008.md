# One Arango Document = One Section, Not One File

Arango documents are section-granularity, not file-granularity. Each document is a
focused, concise chunk about one thing — typically one ID-bearing section (DD-*, DP-*,
FR-*, CG-*).

A 3000-line file like `design/decisions/architecture.md` becomes ~20 Arango documents,
each independently addressable and linkable via graph edges. Queries return just the
relevant section + its graph neighbors, not the entire file.

## Subsection Rule

The ID (DD-ARCH-09, DP-11, etc.) is the natural granularity. Subsections within one ID
stay together — they describe aspects of the same decision. If a subsection is independently
referenced by other documents and has its own heading, it may be split into a separate
document with a `parent` edge back to its ID.

## Rationale

The Orama spike proved that file-level granularity overfetches — a query for "saga
compensation" shouldn't return the entire architecture decisions file. The graph model
requires fine-grained nodes to create meaningful edges. Section-level documents are
small enough to return directly to agents and large enough to be self-contained.
