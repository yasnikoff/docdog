# No Multi-Inclusion — One Section Belongs to One Index

A section file belongs to exactly one index file. Multiple access paths to the same
section are the graph's job (edges), not the file structure's job.

## Why Not Multi-Inclusion

- Unclear ownership — which index is responsible when the section changes?
- Duplicates what the graph already does (edges provide multi-path discovery)
- Complicates the indexer (shared ownership, dedup, cascading updates)
- The 1:1 mapping between file and Arango vertex stays simple

## Cross-Cutting Discovery

DD-ARCH-09 belongs to `architecture.index.md`. If it's also relevant to workflow
patterns, that's a `cross_cutting` or `references` edge in the graph — not a second
file inclusion. The graph handles multi-path discovery; the filesystem handles ownership.

## Rationale

Separation of concerns. Filesystem = authoring and ownership. Graph = discovery and
relationships. Mixing the two creates maintenance burden for something the graph solves
better.
