# Project-Level Scripts and Skills as Extension Mechanism

`.docdog/scripts/` holds project-specific TypeScript/JS files for deterministic
operations that don't belong in docdog core. `.docdog/skills/` holds provider-neutral
markdown skill definitions.

## Scripts

Run via `docdog run <name>`. The runner resolves `.docdog/scripts/<name>.ts`,
loads config, connects to ArangoDB, and calls the script's default export with a
`ScriptContext` (config, db, projectRoot, args).

## Skills

Shipped as package source in `skills/`. `docdog init` copies them to `.docdog/skills/`.
`docdog templates refresh` syncs updates. Skills reference MCP tools, not CLI commands.

## Lifecycle

No formal one-off vs permanent distinction. Delete when done — git history preserves it.

## Rationale

Docdog core handles generic operations. Every project has unique formats and workflows
that don't generalize. Scripts give projects a first-class way to handle these without
forking docdog.
