# Edge Metadata Is Intrinsic Properties, Not Relevance Scores

Edge attributes must be intrinsic to the relationship — facts that don't change
depending on who's querying or why. Agents compute relevance dynamically based on
task context + intrinsic edge properties.

## Edges Carry (Intrinsic)

- `type` — relationship category (from edge collection)
- `role` — directional meaning within the type (`defines`, `constrains`, etc.)
- `context` — one-line factual summary of what connects the two vertices
- `source` — who created the edge (indexer, skill, human)
- `date` — when created/updated
- `discovered_via` — `explicit` (written in markdown) or `inferred` (agent extracted)
- `anchor_text` — the actual text that triggered edge creation
- `status` — `current` | `superseded` | `deprecated`

## Edges Do NOT Carry (Query-Dependent)

- ~~`weight`~~ — relevance to what? Depends on the task.
- ~~`confidence`~~ — confident for what purpose?
- Any pre-computed relevance score.

## Rationale

An edge between DD-ARCH-19 and DP-11 is critical when designing a workflow,
irrelevant when configuring logging. Static relevance scores would be wrong for
most queries. Intrinsic properties are always true; relevance is always contextual.
