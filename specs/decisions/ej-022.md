# Single Database, Scope as Per-Document String Field

Replaces EJ-016 (database-per-scope). All data lives in one ArangoDB database.
Every vertex carries a `scope` field — a free string, default `"shared"`.

## Why EJ-016 Fails

Cross-database edges are impossible in ArangoDB. EJ-016's workaround (plain `ref_*`
fields resolved by Foxx) means graph traversal stops at scope boundaries. Personal
notes referencing shared decisions — the primary use case — require real edges, which
require the same database.

## Scope Field

Every `VertexBase` carries `scope: string` (default: `"shared"`). Free string — no
enum, no registration.

## Edge Behavior

Edges have no scope field. Edges are transparent — traversal follows edges regardless
of the scope of the vertices they connect. Scope filtering is applied to returned
vertices by the caller.

## Rationale

Per-document scope keeps the graph fully connected. Scope becomes a metadata field
for filtering and sync, not an architectural boundary.
