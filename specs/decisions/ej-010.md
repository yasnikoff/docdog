# Collection-Per-Type + .docdog Config

ArangoDB collections map to document types — one collection per type, not a `type`
field on a generic collection. Edge collections are per relationship category.

## Vertex Collections (MVP)

`decisions`, `requirements`, `principles`, `guidelines`, `terms`, `domain`,
`constraints`, `integrations`

## Edge Collections

`edges_structural`, `edges_semantic`, `edges_temporal`, `edges_dependency`,
`edges_crosscutting`

Edges are cross-collection — `_from` and `_to` use full document IDs
(`collection/key`), any edge can connect any two vertex collections.

## Project Config

Project config lives in `.docdog/config.yaml` in the repository root — not in a
central system database. The MCP server reads the local config to know which ArangoDB
database and collections to use.

## Extensibility

New projects add their own vertex collections (e.g., `tickets`, `runbooks`) via
`vertex_collections` in config. See EJ-021 for the mechanism.

## Rationale

Collection-per-type gives optimal indexing, clearer AQL queries, per-collection
schema validation, and natural extensibility. `.docdog/` config keeps project
configuration with the project, not in a central registry.
