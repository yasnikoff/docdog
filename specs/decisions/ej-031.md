# Pluggable Indexer Parsers via scan_paths Config

The indexer supports multiple parsing strategies per path, declared in `scan_paths`.
Replaces the implicit "one file = one vertex" assumption with explicit parser selection.

## Parser Types

- **default** — one file = one vertex (current behavior)
- **split** — multi-section files split on heading pattern (reuses `ingest split`
  logic at runtime, no file output)
- **table** — markdown table rows become vertices
- **script** — user-provided parser in `.docdog/scripts/`

## Config Format

Backward-compatible: strings still work (treated as default parser).

```yaml
scan_paths:
  - specs/refinements/                    # default parser
  - path: specs/decisions/architecture.md
    parser: split
    split_on: "## DD-"
    collection: decisions
  - path: specs/glossary.md
    parser: table
    collection: terms
    group_by_heading: true
  - path: specs/custom.md
    parser: script
    script: parse-custom
    collection: notes
```

## Multi-Section Change Detection

Vertices matched to file sections by frontmatter `id` field (fallback: content hash).
Removed sections are soft-deleted on re-index. File hash is the fast-path skip;
per-section content hash keys the embedding cache.

## Rationale

EJ-030 requires users keep their existing doc structure. The previous model dictates
format. Pluggable parsers let users declare their structure without rewriting.

The `ingest split` and `ingest stamp` commands remain as one-shot migration tools
for users who *want* to restructure, but are no longer required.
