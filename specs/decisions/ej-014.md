# Git-Optional With Three-Tier Feature Ladder

Docdog is git-free at its core, git-enhanced optionally, with a patches convention
for concurrent branch workflows.

## Tier 1 — No Git (Always Works)

Indexer reads filesystem, compares content hashes against Arango. Works on any branch,
any worktree, outside git entirely. No git dependency in the core.

## Tier 2 — Git Awareness (Optional, Additive)

If `.git` exists and `git.enabled: true` in config, docdog:
- Uses git diff as fast-path optimization (skip unchanged files before hashing)
- Knows which branch it's on
- Tracks `indexed_from_branch` on vertices
- Knows the canonical branch (authoritative docs)

## Tier 3 — Patches Convention (Optional, On Top of Tier 2)

Task branch agents create patch proposals in `.docdog/patches/` instead of directly
modifying specs. Avoids merge conflicts when multiple branches are in flight.

- Each patch: which section to modify, proposed new content, rationale
- Patches indexed into Arango as separate collection (`dd_patches`) with edges to
  modified sections
- `docdog_search` on a task branch can overlay patches on canonical results
- Merge to main -> patches applied to specs -> indexer picks up changes naturally

## Rationale

Git is almost always present in software projects. Ignoring it makes docdog feel like
a poor fit. But hard-coupling excludes non-git use cases. The three-tier ladder means:
works without git, works better with git, handles real-world concurrent workflows with
git + patches. Each tier is additive.
