# Visibility Scopes — Database-Per-Scope With Configurable Sync

**Superseded by EJ-022.** Database-per-scope breaks graph traversal across scopes.

Data organized into visibility scopes, each mapping to a separate ArangoDB database
with its own sync channel. MVP uses two scopes (shared, personal).

## Why This Was Superseded

Cross-database edges are impossible in ArangoDB. The workaround (plain `ref_*` fields
resolved by Foxx) means graph traversal stops at scope boundaries. Personal notes
referencing shared decisions — the primary use case — require real edges, which require
the same database.

See EJ-022 for the replacement: single database with scope as a per-document string field.
