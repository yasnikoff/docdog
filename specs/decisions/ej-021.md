# Custom Vertex and Edge Collections Via Config

Projects extend the built-in collection set by declaring custom collections in
`.docdog/config.yaml`. No code changes required to add a new collection type.

## Config

```yaml
vertex_collections:
  - decisions
  - notes
  - tickets        # custom
  - runbooks       # custom
edge_collections: []   # rarely needed; built-in edge collections cover most cases
```

## Implementation

- System collections (`dd_*`) are frozen constants — always present.
- `getVertexCollections(config)` returns system + user-declared collections.
- All consumers (setup, queries, gc, indexer, MCP tools) call these functions instead
  of constants directly.

## Unknown-Collection Policy

- Section file with unknown `collection` frontmatter value: **skipped with warning** by default.
- `docdog index --create-collections` auto-creates the collection and indexes the file.
  Does NOT persist to config — user must add manually.
- Directory-name inference checks against the full collection list, not just built-ins.

## Rationale

EJ-010 claimed extensibility but had no concrete mechanism. This provides it.
Warn-by-default prevents typos from silently creating garbage collections.
