# Task frontmatter contract

Every task file (`tasks/TASK-NNN/README.md`) carries this
frontmatter. Under DD-034, the frontmatter is *load-bearing* —
a vanilla agent reading the file without docdog must be able to
reconstruct the task's lineage, process, and next actions.

## Required fields

```yaml
---
id: TASK-053
title: "Implement provisioning L3 saga compensation"
collection: tasks
status: planned                       # see status_vocabulary below
date: 2026-04-13
description: "One-line summary for search previews."
---
```

- **`id`** — sequential `TASK-NNN`, zero-padded to three digits.
  Generated by the `next-task-id` script (`docdog run next-task-id`).
- **`title`** — imperative, short, fits a commit subject line.
- **`collection: tasks`** — never omit; this is what the indexer
  routes on.
- **`status`** — one of the values in the `tasks`
  `status_vocabulary`: `planned`, `in_progress`, `blocked`,
  `done`, `abandoned`. The vocabulary lives in the collection's
  concept record (`.docdog/concepts/collection-tasks.md`).
- **`date`** — ISO date. When the task was created.
- **`description`** — one line for search previews.

## Optional but usually-present fields

```yaml
branch: task/TASK-053-provisioning-l3
commit_hash: null                     # set on status: done
artifacts_path: tasks/TASK-053/       # folder under repo root
priority: normal                      # project-specific; free-form
```

- **`branch`** — the git branch name. Conventional format:
  `task/TASK-NNN-kebab-slug`.
- **`commit_hash`** — nullable until the task lands. Set on
  finalize. Makes observations pin-able to the exact tree state.
- **`artifacts_path`** — the folder on disk holding supporting
  files (`design.md`, `plan.md`, etc.). Usually just
  `tasks/TASK-NNN/`.

## Relationships block

The heart of DD-034 compliance:

```yaml
relationships:
  - implements: FEAT-PROV-L3          # zero or more
  - derived_from: PROPOSAL-019        # if spec-driven
  - follows_workflow: WF-001          # if a project workflow doc applies
  - references: DD-ARCH-09            # any relevant decision/requirement
  - blocked_by: TASK-048              # dependency you're waiting on
```

**Every id you cite goes here, not just in prose.** The indexer
builds edges from this block automatically. A vanilla agent
reading the file follows these ids directly — no graph query
needed.

**Inverse edges are automatic.** Do not write `superseded_by`,
`depended_on_by`, or `referenced_by` in `relationships:` — write
the forward direction on whichever side makes semantic sense;
traversal finds the inverse.

Common relation types for tasks:

| Type | Meaning | Points to |
|---|---|---|
| `implements` | this task delivers a feature | `features/FEAT-*` |
| `derived_from` | spec-driven: task spawned from a proposal/discussion | `proposals/PROPOSAL-*`, `discussions/DISC-*` |
| `follows_workflow` | task executes steps of a workflow doc | `workflows/WF-*` |
| `references` | task builds on a decision/requirement | `decisions/DD-*`, `requirements/FR-*` |
| `blocked_by` | task can't proceed until another task lands | `tasks/TASK-*` |
| `supersedes` | task replaces an earlier task that was abandoned | `tasks/TASK-*` |

## Body conventions

Below the frontmatter:

```markdown
# <Title>

## Goal
<One sentence: what does this task deliver?>

## Acceptance criteria
- [ ] Concrete, testable item
- [ ] Concrete, testable item

## Context
<Links to decisions, observations, prior art. Resolve ids to file
paths when you can so a vanilla agent can follow them without the
graph.>

## Notes
<Scratch space. Keep self-describing.>
```

## What this contract guarantees

Under DD-034, an agent with zero docdog knowledge should be able
to open any task file and answer:

1. **What is this?** — title, description.
2. **What state is it in?** — status.
3. **What does "done" mean for it?** — acceptance criteria.
4. **What does it connect to?** — relationships block + resolved
   paths in the body.
5. **What process guides it?** — follows_workflow → the workflow
   doc, readable on disk.

If any of those five questions can't be answered from the file
alone, the contract has been violated. Fix the task file; don't
lean on the graph.
